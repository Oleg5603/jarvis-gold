# Network & VPN Guardian — MVP 0.3.2

Рабочая локальная версия 0.3.2 панели мониторинга и Guardian Core для Windows 10/11. Не требует установки
.NET SDK: используется встроенный Windows PowerShell 5.1 и WPF.

## Запуск

1. Откройте папку приложения.
2. Дважды щёлкните `Start-Guardian.cmd`.
3. Подтвердите запрос контроля учётных записей Windows. Права администратора
   нужны для автоматической блокировки приложения ChatGPT при потере Happ.

## Защита Happ и ChatGPT

- после двух подряд проверок без активного маршрута `happ-tun` справа сверху
  появляется красный круг поверх всех окон;
- Guardian запускает `C:\Program Files\FlyFrogLLC\Happ\Happ.exe` и повторяет
  попытку через `happLaunchCooldownSeconds`, пока защищённый маршрут не восстановится;
- для установленного `ChatGPT.exe` создаются отдельные входящее и исходящее
  блокирующие правила Windows Firewall;
- после двух успешных проверок маршрута Happ индикатор исчезает, а правила
  ChatGPT удаляются;
- браузеры и остальной интернет этими правилами не блокируются.

Ошибки запуска Happ и создания правил ChatGPT обрабатываются независимо: сбой
одного действия не отменяет второе. Каждая неудачная попытка записывается в журнал.

Проверка реализована с подтверждением состояния, чтобы одиночная потеря пакета
не включала защиту. `Emergency-Recovery.cmd` снимает как общий Kill Switch, так
и правила ChatGPT.

Приложение измеряет доступность интернета, ping, jitter и packet loss, показывает
активный интерфейс, шлюз, локальный/публичный IP, DNS, обнаруженный VPN-адаптер и
расчётный VPN Health Score. События пишутся локально в `logs/*.jsonl`.

Версия 0.3 использует конечный автомат (`DIRECT`, `VPN_VERIFICATION`, `PROTECTED`,
`DEGRADED`, `LOCKDOWN`) и отдельно проверяет Control Plane и Data Plane. Статус
VPN-клиента сам по себе никогда не даёт `PROTECTED`. Для подтверждения защиты
нужно указать ожидаемый VPN IP и успешно проверить VPN route, DNS и контрольную
точку. Health Score является только дополнительным показателем.

## Важное ограничение безопасности

Kill Switch в MVP включается только вручную и после подтверждения. Он создаёт
обратимое правило Windows Firewall, блокирующее исходящий трафик. Автоматический
fail-closed нельзя безопасно включать до настройки исключений конкретного VPN
(адрес сервера, служба, интерфейс, DHCP/DNS). Отключить созданные правила можно
кнопкой приложения либо командой администратора:

```powershell
Get-NetFirewallRule -Group 'Network VPN Guardian' | Remove-NetFirewallRule
```

Независимый аварийный сценарий — `Emergency-Recovery.cmd`. Он запрашивает права
администратора и удаляет только правила группы `Network VPN Guardian`. Для
проверки компонентов без запуска GUI используйте `Run-SelfTest.cmd`.

## Guardian Core 0.3

`Start-Core-Shadow.cmd` запускает независимый от GUI цикл защиты. По умолчанию
`failClosedMode` равен `Shadow`: Core ничего не блокирует, а журналирует момент,
причину и ожидаемое действие. Direct Public IP изучается при прямом соединении;
VPN Public IP подтверждается после трёх одинаковых здоровых наблюдений через VPN.

Для reconnect задайте `vpnConnectionName` (Windows VPN / `rasdial`) либо
`vpnReconnectCommand`. Для реального режима `Automatic` обязательно заполните
`vpnServerIps`: эти адреса получают host-route для возможности поднять VPN после
удаления небезопасного физического default route. Без whitelist блокировка
прерывается с ошибкой безопасности.

Порядок испытаний: `Shadow` → ручная проверка → `Automatic`. Полный сценарий и
критерий 100 физических циклов описаны в `ACCEPTANCE-TEST.md`.

## Настройка

Параметры находятся в `config.json`. Чтобы включить проверку IP-утечки, укажите
ожидаемый публичный VPN IP в `expectedVpnPublicIp`. Шаблоны имён VPN-интерфейсов
можно дополнить в `vpnInterfacePatterns`.

## Границы версии 0.3

Это первый этап ТЗ, а не промышленная реализация всех 45 разделов. Ещё не входят:
WFP-драйвер, packet capture/PCAP, per-process firewall, интеграции с API разных
VPN-клиентов, continuous traceroute, служба/watchdog и AI-диагностика.
